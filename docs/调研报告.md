# Tinycast → Windows 可行性调研

- **对象：** [abue-ammar/tinycast](https://github.com/abue-ammar/tinycast)
- **目标：** 在 Windows 上重写同类产品，尽量保持原功能、原 UI、以及 **约 5 MB 磁盘 / 常驻 < 100 MB 内存**
- **工作目录：** `D:\VscodeWorkSpace\deploy-project\learning\win-tinycast`
- **调研日期：** 2026-08-28
- **上游对照版本：** 稳定版 `v0.10.2`（commit `7a79585` / 仓库当时 `main` 为 `b1ed5b3`）

本文件是独立重写前的结论，不是 Swift 移植方案。结论先说：**可以做成 Windows 上同类原生启动器，并保住体积和内存预算；不能把现有 Swift 工程转编译过去，也不能在同一预算里 1:1 带上 Raycast 扩展和 Apple Intelligence。**

---

## 1. 原项目是什么

Tinycast 是一台 **macOS 26+ 专用** 的原生启动器（轻量 Raycast），菜单栏附属进程（`LSUIElement`，无 Dock 图标）。

| 项 | 现状 |
|---|---|
| UI | SwiftUI + AppKit |
| 依赖 | **0** 个第三方库，无 SwiftPM |
| 许可 | AGPL-3.0 |
| 姿态 | 只跟最新 macOS，不做兼容层 |
| 源码规模 | 约 394 个 Swift 源文件 / ~2.3 MB；测试约 50 个文件 |
| 安装包 | `v0.10.2` DMG **4.89 MB**，ZIP **4.85 MB** |
| 文档硬预算 | Release 二进制 **< 5 MB**；常驻内存 **40–80 MB**，上限 **100 MB** |

作者自己写过：它快，是因为几乎没有东西。JavaScriptCore 随 macOS 附带，所以 **Raycast 扩展不增加二进制体积**。若改用 QuickJS，光引擎就要 **+1 MB**，所以他们不用。

### 1.1 功能面（按源码体积大致排序）

Extensions（~373 KB）、AI（~248 KB）、Calculator、Emoji、Launcher、Snippets、Palette、HotKeys、Clipboard、Notes、Calendar、WindowManagement、FileSearch、SystemActions、Quicklinks、CustomCommands、Uninstall、Backup、Updates 等。

公开功能包括：应用模糊搜索、自定义命令、内联计算器（数学 / 单位 / 汇率 / 加密货币）、剪贴板历史（文本 + 图片）、代码片段、全局热键 / 应用热键 / 双击修饰键 / Hyper Key、Raycast 扩展、窗口管理、Spotlight 文件搜索、日历、Notes、Emoji、系统操作、卸载扫描、Raycast 导入、AI Chat（含本机 Apple Intelligence）。

### 1.2 架构（和体积相关的部分）

四层，测试 harness 用编译卡住边界：

1. **Pure** — 只有 Foundation；时钟、文件系统、网络一律注入。模糊搜索、计算器、片段模板、窗口几何都在这里。
2. **Effect** — AppKit / AX / Carbon / Spotlight / 剪贴板等平台 I/O。
3. **Observable state** — `@MainActor @Observable`，`AppCore` 是唯一长寿状态所有者。
4. **View** — SwiftUI，薄，不做决策。

`Model/` 禁止 `import AppKit` / `SwiftUI`。新功能必须值得它占用的体积和内存，否则会被拒。

仓库里的 `Tinycast/Windows/` 是 AppKit 窗口（对话框 / HUD / About），**不是 Microsoft Windows。**

## 2. 为什么 Mac 上能做到 5 MB / 100 MB

5 MB 不是因为功能少，而是因为 **运行时全是系统送的**：

| 能力 | macOS 上的成本 |
|---|---|
| Swift / SwiftUI / AppKit | 系统自带 |
| JavaScriptCore（Raycast 扩展） | 系统自带，**0 字节** |
| Spotlight `MDQuery` | 系统自带；查询硬限 1000 条，就是为了不破 100 MB |
| Accessibility `AXUIElement` | 系统自带（窗口管理、粘贴、片段展开） |
| Carbon 热键、EventKit、Keychain、SQLite | 系统自带 |

Windows 没有这份「系统请客」。把同一份 Swift 拿到 Windows：Swift 运行时本身通常就要几十 MB，而且 SwiftUI / AppKit / JSC / AX / Spotlight 都不存在。这是 **重写，不是移植。**

## 3. 总判断

| 问题 | 判断 |
|---|---|
| 现有仓库能否转成 Windows 应用？ | **不能。** 这是 macOS 系统 API 上的专用客户端。 |
| 做成同类 Windows 应用并保住 5 MB / 100 MB？ | **核心子集：可行。完整 1:1：不可行。** |
| 最大障碍 | 体积来自「系统送运行时」；Raycast / JSC 是最大的免费午餐。 |
| 该怎么做 | 新项目、原生栈、砍扩展和本机 AI、先做启动器 + 剪贴板 + 热键 + 计算器。 |

哲学可以搬（原生、零依赖、硬预算）。代码和平台契约搬不了。

许可：AGPL-3.0。若派生自该仓库，Windows 版也必须 AGPL。干净重写可以另选许可，但不能贴他们的 Swift 源码。本项目按 **独立重写** 对待：复用公开文档和 Theme token，不复制 Swift 文件。

## 4. 体积预算在 Windows 上会怎样

| 方案 | 磁盘 ~5 MB | 内存 <100 MB | 说明 |
|---|---|---|---|
| 现有 Swift 直接编译到 Windows | 否 | 勉强可能 | Swift 运行时不在系统里；没有 SwiftUI/AppKit |
| Electron / Tauri + WebView2 | 磁盘或许可，内存否 | **否** | WebView2 常驻 palette 很容易 80–200 MB |
| WinUI 3 / .NET 8 自包含 | **否**（常见 50–80 MB+） | 边缘 | 运行时要打包或另装 |
| WPF / WinForms，**.NET Framework 4.8 框架依赖** | 可以 | 紧张但可做 | 4.8 随 Win10/11 带；WPF 空载常 40–80 MB，剪贴板图片是风险 |
| **C++/Win32 或 Rust + 原生窗口** | **可以** | **可以**（常 15–40 MB） | 唯一和 macOS 同构的路径：系统提供 UI，自己只带业务代码 |
| 嵌 V8 跑 Raycast 扩展 | **否**（+20–40 MB） | 否 | 把 macOS 上「JSC 免费」直接吃掉 |

**预算能保住，前提是放弃 Swift、放弃 Web、放弃自包含 .NET。** 一旦为了扩展生态塞进现代 JS 引擎或 WebView，5 MB 就没了。

本机已有：`rustc 1.96`（`x86_64-pc-windows-msvc`）、Windows 11（build 26200）。和下面的推荐栈匹配。

## 5. 推荐方案

同时保住体积和 UI，只剩一条路：

**Rust + Win32 + Direct2D / DirectWrite + 系统亚克力模糊。**

- 一个 exe，不带运行时、不带 WebView、不带自包含 .NET。
- 面板是无边框置顶窗口：系统 Acrylic 当底，上面铺 40% 黑遮罩，圆角 26，字和行用 Direct2D 按原版 token 画。
- 业务逻辑按原仓库分层重写：纯逻辑（模糊搜、计算器、片段模板）和 Win32 效果层分开。
- 只支持 **Windows 11 24H2+**（build 26100+），和原项目「只跟最新系统」同一姿态。
- 产品身份建议：`com.tinycast.win`。设置窗走 Win11 设置那种分组列表，不要做成第二块命令面板（原版 Settings 也不是面板风格）。

其它选项为什么不选，见第 4 节。

允许的第三方（保持极短；每一项都要报体积增量）：

| Crate | 原因 |
|---|---|
| `windows`（Win32 + DWM + UIAutomation + Shell） | 官方绑定，不是 UI 套件 |
| `rusqlite` + bundled SQLite | 剪贴板 FTS5；约 1 MB |
| `serde` / `serde_json` | 设置、排序、备份 |
| `unicode-segmentation` | 片段光标按字素偏移 |

禁止：winit、wgpu、egui、iced、tao、wry、tokio、默认功能集很肥的 HTTP 客户端、在单独做体积预算之前嵌入任何 JS 引擎。

Release 建议：`lto = true`、`codegen-units = 1`、`opt-level = "s"`、`panic = "abort"`、`strip = true`。

## 6. UI 要对齐什么

原版设计系统写在 `docs/ui.md` 和 `Tinycast/DesignSystem/Theme.swift`。五条不能破：

1. **表面 = 系统窗口后模糊上的 scrim。** 没有实心灰底。深度来自桌面透出来。
2. **一条 alpha ramp，不用灰色。** Dark 是设计，数值是冻结字面量：白墨水叠在暗表面上。Light 是同一档位反相。
3. **顶栏 / 底栏是浮层，不是铬条。** 列表铺满整块面板。
4. **边缘溶解，不是裁切。** 滚动驱动的渐变遮罩。
5. **玻璃只给浮动控件。** 主表面不是 glass；药丸 / 菜单 / 圆钮才是。

关键尺寸（DIP，96 dpi 独立像素 ≡ SwiftUI point）：

| Token | 值 |
|---|---|
| 面板 | 750 × 475 |
| 紧凑高度 | `headerHeight + 2×headerPadding` = 64 |
| 顶边位置 | 工作区高度的 18%，**向下长** |
| 顶栏 / 底栏 | 44 / 52 |
| 行图标槽 | 24 |
| 圆角 | 面板 26、行 10、对话框 20 |
| Dark scrim | 黑 0.40 |
| 选中 / 悬停 | 白 0.10 / 白 0.05 |
| 进入 / 退出 | 180 ms / 120 ms，scale 0.94 |

自己画对话框和 HUD，不用 `MessageBox`。占位符由我们画，不用系统 cue banner（IME 会跳）。快捷键展示改成 Windows 习惯（`Ctrl+K` 而不是 `⌘K`），语言仍是同一套 KeyCap。

图标：应用用 `IShellItemImageFactory` / `ExtractIconEx`；字形用 Segoe Fluent Icons（没有 SF Symbols）。图标缓存按路径 + 修改时间 + DPI + 外观世代；面板关掉就清。

搜索框：宿主一个透明的子 `EDIT`（或 TSF），不要手写组字，否则 CJK 会坏。

验证必须在 **浅色壁纸** 上做。深色壁纸会盖住 scrim / 裁切 bug。

## 7. 功能对照

真正难的不是长得像，而是 **效果层全绑在 macOS 私有能力上。** Pure 层可以换语言重写；Effect 层必须整页换掉。

| 功能 | macOS 依赖 | Windows 对应 | 5MB / 100MB | 1:1 保真 |
|---|---|---|---|---|
| 应用启动器 | `NSWorkspace` + 扫 `.app` + Spotlight 别名 | 开始菜单 `.lnk`、AppX、注册表 App Paths | 容易 | 中：Win32 / UWP / 商店三套目录，没有 `kMDItemAlternateNames` |
| 全局热键 | Carbon `RegisterEventHotKey` | `RegisterHotKey` | 容易 | 容易 |
| 双击修饰键 / Hyper Key / Caps Lock 重映射 | `CGEventTap` + IOKit | `WH_KEYBOARD_LL` + Scan Code Map | 可以 | **很难** |
| 剪贴板历史 | `NSPasteboard` 轮询 + SQLite FTS5 | `AddClipboardFormatListener` + 自带 SQLite | 可以 | 中：图片格式、UWP 剪贴板、排除密码管理器 |
| 计算器 / 汇率 | 纯逻辑 + HTTPS | 原样可做 | 容易 | 容易 |
| 代码片段展开 | AX 改文本 + `CGEventTap` | UI Automation + `SendInput` | 可以 | **很难**：Win32 / WPF / UWP / 浏览器 / Electron / 游戏全屏各一套坑 |
| 窗口管理 | `AXUIElement` + 合成 Dock 手势切 Space | `SetWindowPos` / DWM / Virtual Desktop | 几何容易 | 切虚拟桌面比 macOS 更正规；多 DPI、被提升的窗口仍烦 |
| 文件搜索 | Spotlight `MDQuery`（硬限 1000） | Windows Search，或 Everything IPC | 可以 | 中：Windows Search 质量不稳定 |
| 日历 / 入会 | EventKit | WinRT Appointments 或 Outlook/Graph | 可以 | 中：权限和数据源碎片化 |
| Notes | TextKit 2 | 纯文本 HWND / RichEdit | 可以 | 中 |
| 系统操作 | AppKit / CoreAudio / Apple Events | Win32 / WASAPI / WMI | 可以 | 要逐条重做 |
| 卸载扫描 | 扫 `.app` 旁的支持文件 | ARP + AppX + 残留目录 | 可以 | **完全不同的产品** |
| Raycast 导入 | `.rayconfig` + 本机 Raycast 目录 | 无官方 Windows Raycast | — | 导入器可做，用户侧几乎没源 |
| **Raycast 扩展** | **系统 JSC，0 字节** | 无对等引擎。QuickJS +1 MB；V8 炸预算 | **体积死结** | 宿主 API 是 macOS 语义 |
| Apple Intelligence | Foundation Models | 无。Phi-Silica / 云 API | 本机模型会破内存预算 | 云 API 可做 |

**Raycast 扩展是决定性否决项。** 它在 macOS 上免费，是因为 JSC 已在系统里。Windows 上要么牺牲 5 MB（嵌引擎），要么牺牲功能。即便嵌了 QuickJS，大量扩展仍会因 macOS 专用 host API 跑不起来。

Windows 没有 TCC。低级钩子和 UI Automation 可能触发 Defender。和原版一样：只在设置里打开片段 / Hyper 的手势上要授权，启动时不安钩子。

UAC 提升后的窗口可能吃不到 `RegisterHotKey`、也粘贴不进去。未签名本地构建不做 UI Access。

## 8. 建议做成什么样（产品切分）

**可以按原设计做：**  
应用搜索、收藏、全局热键、剪贴板历史（SQLite）、内联计算器、自定义命令、窗口二分 / 四分、有公开 API 的系统操作（锁屏、音量、清空回收站等）、设置窗。

**能做但要换 Windows 实现，手感会差一点：**  
代码片段展开、文件搜索、日历、Notes。

**v1 建议先不做：**  
Raycast 扩展运行时、Apple Intelligence、Caps Lock 当 Hyper Key、关键字监听展开（等面板展开路径稳了再做）。

市场上已经有 PowerToys Command Palette、Flow Launcher、Listary、Fluent Search、Everything、Ditto。Tinycast 在 Mac 上的差异化是 **「真的小 + 能跑 Raycast 扩展 + 零账号」**。搬到 Windows 后扩展优势基本消失，只剩「小而本地」。要对标的是「Windows 上最轻的本地启动器」，不是「Windows 版 Raycast」。

## 9. 体积与内存账

| 块 | 预算 |
|---|---|
| Rust 代码 + Direct2D 胶水 | 2.2 MB |
| SQLite amalgamation | 1.0 MB |
| Segoe 是系统字体；捆绑的模板字形 | 0.2 MB |
| Emoji 目录 | 0.2 MB |
| 预留 / 以后的 QuickJS | 1.2 MB |
| **合计** | **≤ 5.0 MB** |

内存：

- 图标缓存：8 MB 封顶，面板隐藏时丢掉。
- 剪贴板图片：文件在磁盘，内存里只有缩略图，窗口 1000 条。
- 无 URL 缓存，无 WebView 进程。
- 关掉面板后 RSS 必须回到空闲基线（原版 CONTRIBUTING 的同一条）。

空闲托盘目标 15–40 MB；面板打开 < 40 MB；峰值（含剪贴板图）< 80 MB；硬顶 100 MB。

## 10. 平台映射速查

| 上游 | Windows |
|---|---|
| `NSWorkspace` + `.app` 扫描 | Start Menu `.lnk`、`HKLM/HKCU\...\App Paths`、`%ProgramFiles%`、AppX `PackageManager` |
| Spotlight 别名 | `.lnk` 参数 + AppX 显示名 + 文件描述 |
| `RegisterEventHotKey` | `RegisterHotKey` |
| `CGEventTap` | `WH_KEYBOARD_LL`，**只在需要它的功能打开时安装** |
| Caps Lock → Hyper | HKCU Scan Code Map；退出时清掉 |
| `NSPasteboard` 轮询 | `AddClipboardFormatListener`（事件，不是 0.5s 定时器） |
| AX 粘贴 / 片段替换 | UI Automation `ValuePattern` / `TextPattern`；回退 `SendInput` |
| `AXUIElement` 贴边 | `SetWindowPos` + DWM + `IVirtualDesktopManager` |
| Space 手势 | 公开的虚拟桌面 API，不要伪造 HID |
| Spotlight `MDQuery` | Windows Search OLE DB；否则带同样 1000/200 上限的目录遍历 |
| EventKit | WinRT Appointments；v1 可隐藏该开关 |
| `SMAppService` | 未打包：HKCU Run |
| Keychain | DPAPI `CryptProtectData` |
| JavaScriptCore / Foundation Models | v1 不做 |

运行时仍用四层：Pure / Effect / UI 线程状态 / Direct2D 视图。UI 线程 ≡ 原版 `@MainActor`。重活（扫应用、解码图、FTS、HTTP）走线程池，用消息发回 `AppCore`。

## 11. 风险

| 风险 | 处理 |
|---|---|
| Acrylic + 分层 HWND + 圆角裁切是已知 DWM 坑 | 先把面板壳打通；若裁切成方块，改 `UpdateLayeredWindow` 位图路径 |
| 自定义输入框的 IME | 宿主真正的 `EDIT`，不要发明组字 |
| Defender 把 LL 键盘钩当恶意软件 | 只在片段 / Hyper 打开时安装；以后再考虑签名发布 |
| `windows` crate / fmt / panic 把 5 MB 吃掉 | `panic=abort`、`opt-level=s`、按用到的 API 裁 `windows` features |
| 范围膨胀 | 启动器 + 剪贴板 + 计算器 + 热键才是产品；其余都要过预算门 |

## 12. 若开工，建议顺序（本步尚未执行）

本仓库当前只放了 Superpowers skills 和本报告。应用代码还没写。若开始实现：

0. **面板壳：** 托盘、无任务栏、Acrylic + scrim + 26px 圆角、紧凑/展开、搜索框、全局热键、Theme token。过体积门。
1. **启动器：** 索引、模糊分、使用频率、收藏、启动/退出。
2. **剪贴板 + 计算器。**
3. **自定义命令、片段（先做面板展开）、Quicklinks、Emoji。**
4. **窗口管理 + 有公开 API 的系统操作。**
5. **文件搜索、Notes、日历（能用再开）、卸载、设置备份。**
6. **HTTP AI；** 若磁盘还剩 ≥ 1.2 MB 再考虑 QuickJS 子集扩展。不要嵌 V8。

每一阶段结束后 Release ≤ 5 MB，面板关掉后 RSS < 100 MB。
